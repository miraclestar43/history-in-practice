# 没事儿多读书（原“每日一鉴”）：内容体验与长期编辑要求

本文补充 `docs/PLAN.md`，作为样稿、日常写作和内容评审的共同标准。

## 用户真正想读的内容

中文约十分钟、英文也约十分钟，认识一段以前不熟悉的历史，读到有意思的人、处境和选择，再将问题带回自己的生活。中英两版可以参照阅读。邮件中文全文在前、英文全文在后；网站默认中文，用 tab 切换英文。公开归档需要长期积累，默认每日一篇新故事，不重复消费旧稿。

用户喜欢小约翰可汗的历史内容带来的阅读兴趣。将这一偏好落实为通用的叙事要求：从具体矛盾切入、把背景说清楚、人物有约束和选择、转折有事实依据、陌生人物也能读懂、细节能帮助理解历史。形成栏目自己的语气，不复制博主口头禅、标志性表达、现成段落或人物标签，也不能让戏剧性取代证据。

不必每篇都有反转，更不应为制造反转隐去关键背景。不是每个故事都能用一句“其实全是利益”解释完。

## 题材范围（2026-10-30 用户更正）

栏目要宽：历史（各地区、各时期）；政治、治理、制度、外交与社会变迁；经济、金融、商业、企业与不确定下的决策；科学家、发明者、艺术家、公众人物、企业家和普通人的具体经历；战争与冲突也在其中，可以写外交、后勤与平民处境，但不加权、不设配额、不作为默认选择。ebook-treasure-chest 书目说明了所需的广度；历史仍是重要来源，但不要求每篇都是战争故事或名人故事。

- 继续使用现有四个轮换类别（中国古代、世界、中国近现代、美国）；主题用标签表示（`supply.TAGS`），战争不成为第五个栏位，不重新设计类别体系。将来如需非历史类别，单独提出，不在此悄悄改。
- 成功、失败、取舍和事后改变的判断都值得写。避免英雄崇拜、事后确定性和硬造的道德教训；应用要从事件本身出发，并说明在哪些情况下这条经验不适用。
- 书名和未核实的简介只是线索，不是已核实的故事；小说和小说化传记不能作为证据（见 `config/book_candidates/`）。

## 一篇好故事的最低要求

- 开头两三句提出具体的问题或处境，避免“纵观历史长河”式铺垫。
- 很快说明谁、何时、何地、想达成什么，以及为什么做起来困难。
- 重点叙述一件事，通常以 2–4 个关键场景推进，不列人物一生年表。
- 至少有一个经过核实、读完记得住的细节；细节服务于理解，不凭空增加画面。
- 清楚展现当时能知道什么、有记录的行动和代价；只有材料写了，才说人物“考虑过”哪些选项。不能事后把结果写成命中注定。
- 用简洁自然的中文，可以有克制幽默；不嘲讽普通人的苦难，不靠猎奇标签和夸张标题维持兴趣。
- 历史本体占最大篇幅（故事与解释合计不少于 55%），应用和思考简短、有抓手。不要让结尾变成重复说教。

篇幅以阅读体验为准，不为凑字数扩写；试稿区间见 `docs/PLAN.md` §3（中文约 2,800–3,600 字，英文约 1,800–2,200 词，均为松参考，各语言分别约十分钟；出处与延伸阅读不计入）。

## 叙事骨架（提纲门槛，v2.2）

提纲阶段先写出有记录的骨架，再写稿；骨架里的每一项都要能指向证据摘录：

1. **矛盾或处境**：当时要解决什么问题，难在哪里。
2. **约束**：钱、时间、信息、制度、他人。
3. **行动与变化**：谁做了什么、发生了什么转折（有记录的）。
4. **后果**：结果如何、谁付出了什么。
5. **一个记得住的细节**，附证据 ID。

不要求每个故事都有“主角在两个选项之间抉择”。制度史、科学史和普通人的经历可以从一个具体事件切入，例如一份报告、一次拒绝、一次调查，不因缺少个人二选一而淘汰。人物的动机、想法或“当时考虑过的选项”，只有材料写了才能写，并标明出处；作者提出的替代选择、反事实和现代讨论，只能放在“为什么会这样”“别照搬的地方”或开放问题里，并明确标为作者提出。每段在内容对象中标注 `kind`：`record`（有记录的叙事）、`interpretation`（作者解释）、`modern`（现代虚构场景）、`uncertainty`（不确定性说明）。

四篇样稿中，“留美幼童”一篇就是没有英雄式抉择、由报告、拒绝与上奏推动的制度故事，用来检验这条规则（见 `samples/C/`）。

## 开放问题与示例解答

每篇至少一个开放问题，并提供一份**示例思路，而非标准答案**。问题应有真实权衡，允许两种以上合理判断，不问“你是否认同诚信很重要”这类答案已写好的题。

推荐顺序：

1. 先给一个与故事相关、也可能出现在生活中的情境。
2. 提出问题，提示读者可以停十秒想一想。
3. 在分隔后的“一个参考思路 / One possible approach”中给出简短示例。
4. 示例说明假设、可执行步骤和另一种可能选择，避免暗示每次都应选择同一种处事策略。

### 问题类型轮换

每篇在 `reflection.type` 标注问题类型，取自固定集合：不确定下决策、分配与归属、何时离开、相信谁、如何纠错、何时等待、如何授权、如何传达坏消息（可扩展）。连续 7 期不重复同一类型。目的在于防止每天都落回“分钱与信任”，让问题跟着故事走，而不是故事去配一个现成的问题。

**仅供说明结构的现代虚构情境：**

> 你参与一个小团队，负责人表示现在资源紧张，项目成功后再补偿大家。你会继续投入多久？哪些信息会改变你的决定？

**一个参考思路：**

> 我会先区分短期困难与长期分配方式：目前资金是否透明、此前承诺有没有兑现、补偿的金额和时间能否明确。可以接受一次有边界的延期，同时约定复盘节点和自己的投入上限。若负责人愿意共享信息、自己也承担代价，我可能继续；若长期只有口头承诺，我会减少投入并准备退出。也有人更看重学习机会或关系，但应清楚自己在交换什么。

这不是对任何真实同事或机构的评判，也不是历史人物的原话。正式文章的现代情境与史料叙述应清楚分开。

网站示例解答可折叠，点击后展开；邮件不依赖交互，将问题先列出，再用留白和明确小标题展示示例。中英示例包含相同假设和权衡。问题及示例都计入十分钟长度预算。

## 来源与继续阅读

每篇结尾分为两层：

- **本篇依据 / Sources**：默认 2–4 项，给出作者或机构、材料名、年份/时代、章节或页码及链接。关键事实可标简短 `[1]` 引用。链接能打开不等于支撑事实，必须实际读到相关内容。
- **想再读一点 / Read more**：默认 1–3 项，每项说明“点开能进一步了解什么”，并标明中文/英文、原典/解释文章、是否需付费等已知情况。不堆裸链接，也不强行满足数量。

延伸阅读可与依据重复，但要写清推荐的具体部分。书籍没有合法在线全文时链接出版社、图书馆或正式目录，不制造下载地址。原典古文较难时，尽量另提供可靠且易读的解释材料。不伪造阅读时长；未完整阅读的书不能声称已通读。

## 每日新内容与长期可持续性

以“事件/片段”识别故事，不以标题字符串识别。一位人物一生可有多个有意义的故事，但同一事件换标题、翻译、视角或类别，仍视为重复。回顾已有内容可做明确标注的附加模块，不占当天新故事名额。

每个具体片段在 episode 注册表中有不可变 ID，宏观事件（战争、远征、运动）记为 `parent_event`，同一宏观事件下可以有多篇不同片段。判断是否重复，依据规范出处位置（作品 + 卷/章 + 段落）、人物（含繁简与别名）、时间、地点和行为，QID 只是可选外部关联（见 `docs/PLAN.md` §4.4）。同一主角 90 天内再现须换不同片段与不同问题。提纲生成前查重，成稿后再查一次；查重范围包括已发布、已排期、已准备和已预留的稿件。

归档一并进入 GitHub：正式结构化内容和派生的中英文 Markdown 都要能浏览。网站与邮件从同一正式内容版本渲染，Markdown 由程序派生，不能形成三份手改的正文。GitHub 是持久归档；StarHub 是现有阅读入口，本要求不自动意味着另建一个 GitHub Pages 网站。

每天是运行目标：提前生成和审核，保持约 14 天未发布合格库存，各类有足够储备；低于 7 天告警。默认自动供稿：候选由模型提出线索、由程序取回并分级证据，满足自动准入规则的直接进入写作队列；来源冲突、身份不明、核心细节缺乏支撑、疑似重复等异常进入待处理队列，不阻塞其他合格稿。人工策划是可选的，不是每周必经步骤（见 `docs/PLAN.md` §4.2）。按过去 30 天消耗速度补充，不能把启动时的 40 个选题视为长期内容来源。每周规划补充至少能覆盖下周消耗的合格新稿及余量，记录候选→可用稿通过率，持续扩展地区、年代、人物和题材。

轮换、去重和库存必须同时满足；类别不足时提前补稿。临近发送仍无合格内容时通知维护者，不偷偷重发旧文、不将未核实材料包装成历史。不能为了声称全年不断更降低事实标准。

## 样稿评审维度

逐篇说明：

1. 开头是否让人想继续读，哪里出现注意力下降。
2. 不认识这些人物的人能否明白背景。
3. 哪个具体细节最值得记住，它的出处是什么。
4. 哪句话过度解释或把人物写成单一标签。
5. 开放问题是否真的可以有不同答案，示例是否给出假设与权衡。
6. 应用与史事是否有关联，有没有生搬硬套。
7. 哪些出处能核实正文，延伸阅读是否值得点开。
8. 包含问题与示例后，中文与英文各自的阅读时间是否分别接近十分钟目标。

“模型说很好”不算验收证据；提供四类样稿和实际呈现，再据读者反馈调整。

英文应自然地道，允许重组句法和节奏，逐项保持事实、数字、判断及来源一致。最新要求见 `docs/USER_REQUIREMENTS_20261030.md`，优先于旧样稿的合计阅读时长。
