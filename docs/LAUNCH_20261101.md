## 2. Model (owner decision 2026-11-01)

**history-in-practice:** Claude drafts, writes the English, runs the edit rounds and proposes candidates (`writer.py`), and runs the final editor and the context review. All of it goes through the Pi's Claude Code CLI on the claude.ai Max subscription.
- **Verified with one real call** (`hip doctor --probe`): `claude-opus-5-5`, CLI 2.1.308, `apiKeySource: none`.
- **If Claude is unavailable:** nothing is drafted, the nightly job exits 4 and an alert is sent. There is no MiMo fallback.
- **Separation kept:** writing and review are still separate calls with separate prompts and records.
- **MiMo/Hermes** stay in the history and config only.

**Why not Hermes's Claude.** Hermes's only Anthropic credential is a pay-per-token API key (`claude_paid`), and Hermes's default model is global. Neither is used.

**news-intel:** branch `feature/claude-provider`, not merged.
- **Change:** `LLM_PROVIDER=claude_cli` uses the same Claude Code CLI login. Hermes is untouched.
- **Dry run on a DB copy:** both editions called `claude-opus-5-5`. Both top stories still fell back to the rule summary because of the validator (an English gloss on 国铁集团; an untraceable number), not because of the model.
- See `pi-news-intel/docs/CLAUDE_PROVIDER_20261101.md` on that branch.

**Login.** The subscription login's refresh token expires in about 28 days (around 2026-11-29). The alert warns 7 days ahead. Renew it with `CLAUDE_CONFIG_DIR=~/.config/history-in-practice/claude ~/.local/bin/claude auth login`.

## 6. Rollback

**Stop sending:**
- `systemctl --user disable --now hip-send.timer hip-send-retry.timer hip-prepare.timer`;
- `EMAIL_SEND_ENABLED=false`.

Nothing in flight is resent later; unfinished issues become `overdue`.

**Website:** revert the merge commit on `website_test` main (`git revert -m 1 <merge>`, then push). The homepage and other pages return to their previous bytes.

**Model:** history-in-practice has no other writer by design. If Claude is down, jobs pause and alert.

**news-intel:** set `LLM_PROVIDER=hermes_cli` in `.env` again.
