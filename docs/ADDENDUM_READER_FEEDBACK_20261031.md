# 读者反馈补充：易读叙事、中国主线、邮件投递与栏目命名

日期：2026-10-31（America/Los_Angeles）。

这是实际读者反馈，优先于旧 PLAN、EDITORIAL_BRIEF、固定四槽轮换和旧提示中与本文件冲突的要求。本文件不授权正式上线、合并 main、开启定时器或追加真实邮件。继续正在运行的修复链，不重启已完成步骤、不覆盖并发工作。

## 一、实际收到与实际阅读反馈

- 读者本人确认收到一份 Snow 测试邮件，初始进入 Spam，已手动选择 Report not spam。不能再写“无人收到／无人看过任何文章”。
- 这不等于另一位收件人也确认收件，不等于旧样稿全部读过或获批，更不等于当前 Snow 的事实错误已完成修复。
- 本次阅读感觉偏难：陌生人名、地区名、公司名与多组数字叠加；前部数据铺陈冗长，读者尚未进入故事就需要记住和区分许多东西。
- 外国题材的陌生感会增加负担，但不能把原因全部归于“外国故事”。本轮编辑要直接处理叙事顺序、信息负担和背景解释；外国故事也应该让没有专业背景的读者读懂。

## 二、先让人进入故事，再展示证据

目标仍是中文、英文各约十分钟，英文自然、信息一致。此次反馈不是要求把所有文章缩成短摘要，也不要求用闲话、重复分析或编造场景填满十分钟。

1. 开头先讲清一个可理解的问题或处境：谁遇到了什么，为什么值得关心，做起来难在哪里。随后让行动、发现、转折和结果推动阅读。
2. 人物第一次出现说明身份与本件事的关系。通常先建立一两位核心人物即可；这是一条写作提醒，不是硬性人物数量上限。其他人需要时再引入。
3. 外国人名优先用常用中文译名，首次必要时括注英文；后文使用一致简称或身份。避免同一人交替出现全名、姓氏、头衔，让读者以为是几个人。
4. 地名只保留对理解事件必要的层级及相对关系；先说明“同一城市的两个社区”等读者需要的关系，再按需要给出具体名称。不能把不同地方或机构合并成一个，也不删去会改变因果判断的差异。
5. 同时出现多家机构/公司时，用准确、稳定、容易记的简称，并说明各自角色。完整原名留在首次说明和出处，不反复堆叠。
6. 数字必须有作用：比较什么、为什么要比、看完能理解什么。开头不要让读者逐行消化表格或连续记忆多个样本数、死亡数、户数、年份。
7. 正文优先保留改变判断的核心对比、量级或比例，并说清单位/分母。支撑性的完整统计可放在后部小表或“证据细节”中供愿意深读者查看。不得把死亡率说成病例数，把户数说成人数，或删除结论必需的限制。
8. 年代、制度与文化背景按需解释，避免读者必须先懂一段外国通史或流行病学才能跟上。
9. 结尾围绕一个或少数相连的洞见，说明具体适用场景、取舍和不能照搬的地方；不要重复一串抽象道理。
10. 修订不得补造对白、动机、想法和现场细节；可读性与事实正确是两项独立要求，都必须通过。

Snow 的示范修订方向：先让读者明白调查要解决的疑问，以及两家供水公司为何构成有意义的对比；读者需要比较数字时，再给必要对照。不是先摆一串数字再等待读者自行拼出问题。已确认的登记总署后续调查错误按独立修复要求处理，不能因改叙事而掩盖。

## 三、题材主线：中国古今为重，其他地区保持变化

用户的新偏好：

- 约每七篇中四篇中国故事、三篇其他地区故事，以中国历史与人物经历作为熟悉且有延续性的主线。
- 中国古代和中国近现代都要有。可先用两篇古代、两篇近现代作参考，但并未要求每周死守二比二。
- 其他约三篇可以来自欧洲、其他亚洲地区、美国等；不是固定三个地域各一篇，不把其他地区永久排除。
- 不固定星期几对应某一类，不强制每一个自然周精确填满配额。短期可因质量、来源和专题做适度调整，再在后续排期中平衡。
- 不能为凑配比降低事实标准、强行发布待审稿，或用同一事件改标题填空。

选题仍覆盖政治、治理、制度、经济金融、商业、科学、人物传记与普通人的经历，战争只是其中一部分，不加权、不设专门配额。

多样性不只看国别。连续几篇都写帝王将相或军事胜败，即使国别不同也会单调；应变化人物角色、时代、问题、成败与现代应用。可偶尔围绕一个问题做中外相照的相邻故事，形成联系，但不牺牲独立可读性，也不要求读者追完系列才能理解。

## 四、让排期、供稿与库存一起改变

旧 rotation=[china_ancient, world, china_modern, us] 等频循环，约一半中国，不能继续作为新偏好的实现。

- 可以保留已有四个 category 标签以兼容存量数据。中国古今两类合计约四成稿／七篇；world 与 us 合计约三篇。欧洲、亚洲等用 region 标签区分；不要把整个美洲都自动归入 US。
- 请据此实现一个简单、可解释、可恢复的偏好排期机制。先生成并持久化接下来一段的具体合格稿顺序，再按序执行；重试/恢复不能每次重新随机选择当天故事。
- 配比是软目标；实际顺序还考虑质量、事件/人物去重、主题变化和可用库存。不制造复杂的跨周排期优化器，也不要求每周人工审批。
- 供稿按未来计划的实际缺口补充，不是继续机械地把四类补到相同篇数。
- 库存覆盖仍需根据新排期的可执行顺序计算；不能把总文章数直接当作天数，也不能沿用旧四槽轮换得出的天数却宣称满足新配比。
- 测试发送不消耗正式轮换槽；保留正式历史、测试身份、修复版本及投递幂等记录，不回写已发内容。
- 提供一个“拟排接下来七篇”的只读预览，给出类别、地区、主题和简短选用原因，便于确认主线与变化。拟排不等于已发布，也不自动启用任务。
- 更新 EDITORIAL_BRIEF、PLAN、配置说明、供稿提示和相关测试，避免文档与实际代码各说一套。

## 五、把易读性变成真实检查，而不只多加一个模型评分

1. 先在同一篇已有文章上验证：修订前后对照开头、机构简称、地理解释、核心数据呈现和叙事推进。Snow 完成事实修复后可作为外国题材样例。
2. 再做一篇中国故事样例，证明易读性来自写法改进，不能靠换成熟悉题材掩盖结构问题。
3. 终审明确检查：不了解背景的人能否在开头说清“谁遇到什么问题”；关键角色是否容易区分；地理/数字是否确实必要；结论是否依然有完整上下文支撑。
4. 自动统计姓名/数字数量仅作提示，不能用机械阈值代替阅读，也不能通过删掉必要事实来刷指标。
5. 输出真实中英文阅读估算及渲染预览，等待读者体验反馈；不伪称两位读者已批准。

## 六、邮件进 Spam：事实、待查项与处理

本轮只读检查了用户收到的那一封测试邮件的元数据，未修改邮箱标签/联系人/过滤器，也未另发邮件。

已确认：
- Gmail 收件头 SPF=pass。
- 自有发送子域 read.starhub.vip 的 DKIM=pass；另有发送服务的 DKIM=pass。
- 当前标签为 INBOX 与 CATEGORY_UPDATES，符合用户已移出垃圾箱的反馈。
- 所查看的 Authentication-Results 未列 DMARC 结果。不能由此断言 DMARC 已配置或缺失，也不能只因 Resend 域名 Verified 就声称 DMARC 通过。
- 未获得 Gmail 最初 Spam 提示的理由，因此尚未确证单一原因。

待 Claude 核实：
- 查实际 _dmarc.read.starhub.vip 及适用父域策略，确认有效性与 From/SPF/DKIM 对齐。区分记录不存在、继承策略、DNS 传播和邮件生成时的状态。
- 查看 Resend 本次邮件的 Deliverability Insights/投递事件，如现有权限可用。SMTP accepted、provider delivered 与 Gmail Inbox/Spam 是不同层次。
- 新发送域/子域信誉、发送基础设施、内容/链接与收件人信号都可能影响分类。预览 pages.dev 链接与发信域不同只能记为待检查因素，不得未经证据就认定为本次原因。
- 检查 MIME 的纯文本版本、大小、可见发信身份和回信地址、是否存在不必要的重定向/跟踪。保持正常内容和稳定低量发送，不买名单、不批量发测试来“养号”、不建议购买专用 IP。
- 不未经允许改变根域现有 SPF/DMARC 或提高到 reject/quarantine。需要调整时先检查已有邮件服务和子域影响，具体改动按现有授权处理。
- 用户已点 Not spam 是有用反馈。添加联系人或给该发件人设“Never send it to Spam”过滤器是可选的收件人设置，不是自动替用户完成的动作，也不能代替发送端认证与信誉检查。
- 后续正常发送再记录实际投递表现；本文件不授权追加第二封 TEST。

## 七、栏目名和日期：候选待选，格式先统一

用户觉得“每日一鉴”过于普通，不能激起阅读动力，希望名字更有吸引力，并带日期。目前尚未选定新名字，不应擅自把某个候选写成最终品牌。

候选：
- 往事有用：直接表达从故事中获得可用认识。
- 人间有前例：有好奇心，能涵盖历史、人物、商业与社会。
- 旧事新眼：强调重新理解，稍有文气。
- 往事里的门道：更口语，强调故事与思考。
- 前事今用：简洁，实用意味更强。
- 往事有回声：更温和、叙事化，实用含义较间接。

邮件主题与网站栏目标题建议使用：
【栏目名】YYYY.MM.DD｜当期具体故事标题

例如以下仅为格式演示，不宣称已有这篇稿件：
【往事有用】2026.10.31｜一封劝告，为什么没能改变他的决定？

- 栏目名是识别，真正激起打开兴趣的是具体故事标题。标题应提出真实问题/冲突，不能夸大或隐藏关键事实制造反转。
- 日期使用 America/Los_Angeles 的真实期次/出版日期；补发/更正保留原期次及清楚的更正时间，不改旧发送历史。
- 等用户选定名字后，统一修改 From 显示名、邮件主题/正文页眉、网站标题、归档文案和文档；保持 history@read.starhub.vip 发送地址及既有 edition/test ID、hash/投递历史语义。品牌变更不是创建新测试身份或重发的理由。
