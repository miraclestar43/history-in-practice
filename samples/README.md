## 怎么做出来的

1. **来源**：按“适配器 + 具体文档”取回正文（`validation/fetch_source.py`），先分级再缓存，记录 SHA-256 与取回时间。结果见 `validation/fetch_results.json`。
2. **证据包**：用起止锚点从缓存文本中机械截取摘录（`validation/build_evidence.py`），保证每条引语都是原文逐字片段。
3. **编辑简报**：由 Claude（Opus）作为校准编辑撰写，只列有记录的事实、证据 ID 与必须披露的不确定性。
4. **模型三步**：经项目级隔离调用器（0 工具、无 SOUL/memory/AGENTS 注入）调用 Hermes / mimo-v2.6-pro。三步依次为中文稿、按证据审稿、英文版，耗时见上表。
5. **编辑修改**：Claude 对照审稿意见与证据逐条修改，记录在 `editor_log.json`。审稿发现的问题有两类：
   - 模型写错：时间系错、把作者推断写成史实、误读原文主语、引语加了原文没有的强度、把非引语加上引号；
   - 证据包截得太短：模型写对了，但相关原文不在摘录里。这种情况下扩充摘录，而不是删掉正确内容。
6. **程序检查**（`validation/check_article.py`）：
   - 四篇均无 BLOCK；
   - 古文引语经繁简转换后都在所引摘录中，英文引语逐字出现在所引摘录中；
   - 剩余 CHECK 只是年号、月份这类中英数字写法差异。
7. **渲染**（`validation/render.py`）：同一对象生成邮件、网页数据与 Markdown；网页由无头 Firefox 实际渲染并截图。

**编辑介入的实际情况**：每篇 10–13 处修改，多数是事实收紧与证据补充；每篇的“今天可以怎么用”第一条都和开放问题场景重复，因此被替换。编辑工作由 Claude 完成，用时没有单独计量，所以本阶段不能据此估算长期人工成本。模型自审抓到了大部分事实问题，但抓不到场景重复、证据包本身的缺口这类问题。
